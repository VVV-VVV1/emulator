# Эмулятор 16-битного стекового процессора

Учебный эмулятор процессора с **безадресной системой команд**, реализованный на C++. Проект моделирует выборку и исполнение машинных инструкций, работу регистрового стека и обращение к единой оперативной памяти. Целевая задача варианта 16 — **суммирование элементов массива**.

## Архитектура

- **Разрядность:** 16 бит; значения и машинные инструкции представлены `uint16_t`.
- **Память:** единое адресное пространство команд и данных (архитектура фон Неймана), `65536` ячеек по 16 бит. Адресация — по словам.
- **Размещение:** программа загружается начиная с `0x0000`; область данных в учебных примерах начинается с `0x0800`.
- **Стек:** регистровый, ёмкость 16 элементов. Вершина — `registers[0]`; `SP` равен количеству занятых элементов (от 0 до 16).
- **Регистры/состояние CPU:** `PC` (адрес следующей инструкции), `IR` (текущая инструкция), `FLAGS` (зарезервирован; обновление пока не реализовано), `halted` (признак остановки).

Стек хранится в объекте `RegisterStack`, поэтому отдельный дублирующий `SP` внутри `CPU` не используется.

## Формат машинных инструкций

Каждая инструкция занимает **одно 16-битное слово**.

- Если старший бит равен `1`, инструкция интерпретируется как `PUSH` (`LIT`): младшие 15 бит содержат непосредственно загружаемое значение. Диапазон литерала — `0…32767`.
- Если старший бит равен `0`, слово рассматривается как код операции (`opcode`) и обрабатывается в `CPU::step()`.

Например, `0x800A` означает `PUSH 10`, а `0x0001` — `ADD`.

> Коды операций ниже назначены в рамках этого проекта; это не универсальные машинные коды реального процессора.

## Система команд

В примерах стек записывается как `[вершина, следующий элемент, …]`.

| Команда | Машинный код | Назначение | Реализация |
|---|---|---|---|
| `PUSH` / `LIT` | `0x8000`–`0xFFFF` | Помещает литерал на вершину стека | `value = IR & 0x7FFF`; `stack.push(value)` |
| `ADD` | `0x0001` | Складывает два верхних значения | Извлекает `b`, затем `a`; помещает `uint16_t(a + b)` |
| `SUB` | `0x0002` | Вычитает верхнее значение из следующего | Извлекает `b`, затем `a`; помещает `uint16_t(a - b)` |
| `DUP` | `0x0003` | Дублирует вершину стека | `stack.push(stack.peek())` (через временную переменную) |
| `DROP` | `0x0004` | Удаляет вершину стека | `stack.pop()` |
| `SWAP` | `0x0005` | Меняет местами два верхних элемента | Два `pop()`, затем два `push()` в обратном порядке |
| `READ` | `0x0006` | Считывает слово из памяти | Извлекает адрес и помещает `memory.read(address)` |
| `WRITE` | `0x0007` | Записывает слово в память | Извлекает адрес, затем значение; вызывает `memory.write(address, value)` |
| `JMP` | `0x0008` | Безусловный переход | Извлекает адрес и присваивает его `PC` |
| `JNZ` | `0x0009` | Переход, если условие не равно нулю | Извлекает адрес, затем условие; если `condition != 0`, устанавливает `PC = address` |
| `HALT` | `0x000A` | Останавливает выполнение | Устанавливает `halted = true` |

### Примеры работы со стеком

```text
PUSH 20    []           → [20]
PUSH 10    [20]         → [10, 20]
SUB        [10, 20]     → [10]       (20 − 10)
DUP        [10]         → [10, 10]
PUSH 5     [10, 10]     → [5, 10, 10]
SWAP       [5, 10, 10]  → [10, 5, 10]
DROP       [10, 5, 10]  → [5, 10]
```

### Работа с памятью

`READ` заменяет адрес на вершине стека значением из памяти, не изменяя число элементов:

```text
Memory[0x0800] = 25
PUSH 0x0800    []       → [0x0800]
READ           [0x0800] → [25]
```

`WRITE` ожидает **адрес на вершине**, а **значение под ним**; оба операнда удаляются:

```text
PUSH 50       []           → [50]
PUSH 0x0801   [50]         → [0x0801, 50]
WRITE         [0x0801, 50] → []
# Memory[0x0801] = 50
```

### Переходы и остановка

`JMP` получает адрес из стека. `JNZ` ожидает на вершине адрес, под ним — условие; **оба значения извлекаются независимо от того, выполнен переход или нет**. Условие проверяется непосредственно по значению из стека, а не по `FLAGS`.

```text
PUSH 1
PUSH 10
JNZ           # PC = 10, поскольку 1 != 0
```

`HALT` устанавливает признак остановки. Последующие вызовы `step()` сразу возвращаются без исполнения новых инструкций.

## Цикл исполнения

Метод `CPU::step()`:

1. Проверяет `halted`.
2. Считывает инструкцию из `memory[PC]` в `IR`.
3. Увеличивает `PC` на единицу.
4. Если установлен старший бит — выполняет `PUSH`; иначе выбирает обработчик по `switch (IR)`.
5. При `JMP` или успешном `JNZ` заменяет `PC` адресом перехода.

Для неподдерживаемого кода операции генерируется `std::runtime_error("Unknown instruction")`. Стек проверяет переполнение и опустошение; операции, требующие двух операндов, проверяют их наличие до извлечения.

## Структура исходного кода

| Файл | Назначение |

| `main.cpp` | Загрузка тестовой программы и её запуск |

## Проверенный пример

В тестовой программе счётчик в `Memory[0x0800]` уменьшается с `3` до `0` с помощью `SUB`, `READ`, `WRITE`, `JMP` и `JNZ`, после чего выполняется `HALT`.

Ожидаемый и полученный результат:

```text
PC = 13
SP = 0
Counter = 0
Halted = 1
Steps = 30
```

## Текущие ограничения и планы

- `FLAGS` объявлен, но флаги арифметических операций пока не обновляются.
- Арифметика выполняется над `uint16_t`: результат приводится к 16 битам (переполнение и отрицательный результат оборачиваются по модулю `65536`).
- Одна инструкция `PUSH` не может непосредственно загрузить литерал больше `32767`.
- Пока машинные слова программы загружаются вручную через `CPU::loadWord()`; текстовый ассемблер ещё не реализован.
- Целевая программа суммирования массива будет добавлена на следующем этапе.

## Примечание о методике

Принцип единой памяти и регистрового стека выбран по учебному описанию стекового процессора. Конкретные числовые коды команд, размер регистрового стека и отдельные детали поведения (`JNZ` при ненулевом условии) зафиксированы как проектные решения этого эмулятора.

## Реализация ассемблера и выполнение программы

На данном этапе разработан двухпроходный ассемблер, позволяющий создавать и загружать программы для эмулятора из текстовых файлов с расширением `.asm`.

### Реализованные возможности

- Создан класс `Assembler` для преобразования ассемблерных инструкций в 16-битные машинные коды.
- Реализована загрузка инструкций из внешнего файла `program.asm`.
- Добавлена поддержка именованных меток (`LOOP:`, `END:`) и обращения к ним через `PUSH`.
- Реализован двухпроходный алгоритм трансляции: на первом проходе определяются адреса меток, на втором формируются машинные коды.
- Добавлена директива `ORG` для размещения инструкций и данных по заданным адресам оперативной памяти.
- Добавлена директива `WORD` для записи 16-битных значений в память.
- Реализована загрузка результата ассемблирования в память процессора с сохранением адресов.

### Проверка программы варианта 16

Программа вычисления суммы элементов массива перенесена в файл `program.asm`. Для работы используются именованные метки, стековые инструкции, условные переходы и операции чтения и записи памяти.

Исходный массив: `[10, 20, 30, 40]`.

Результат выполнения:

```text
SUM = 100
INDEX = 2053
COUNT = 0
SP = 0
Halted = 1
Steps = 97
```

Проверка подтвердила корректное вычисление суммы, обработку всех элементов массива, освобождение стека и штатное завершение программы.
